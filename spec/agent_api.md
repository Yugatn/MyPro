# Agent API Specification

MyPro is agent-ready at the contract level. MCP is an integration protocol, not the canonical project model.

## Principle

Agents operate on typed verbs over project data.

Examples:

- inspect_project
- inspect_asset
- inspect_analysis
- inspect_provenance
- create_proposal
- validate_proposal
- preview_action
- apply_action
- create_revision
- restore_revision
- export_timeline
- request_render
- inspect_render_receipt

An agent call must not receive implicit authority from the existence of a tool.

## Proposal boundary

A proposal contains:

- proposal id;
- intent;
- constraints;
- target assets/project entities;
- proposed operations;
- alternatives where applicable;
- confidence or uncertainty when generated by a model;
- provenance;
- reversibility;
- required capabilities.

## Action boundary

Applying a proposal is a separate operation. Core validates:

- schema;
- target identity;
- current revision;
- capability scope;
- policy;
- invariant preconditions.

A successful action creates an event and a recoverable revision.

## MCP

MCP can expose these typed operations to external agents.

The MCP adapter must remain a thin protocol boundary. It must not bypass Core authorization, project persistence, provenance or invariant checks.

## Headless operation

The same contracts must work without RosEdit. CLI, server-side workers, test harnesses and future agent runtimes can therefore share the Evidence Core.
